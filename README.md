# 📱 توثيق النظام الشامل: تطبيق نقطة بيع كروت شبكات المايكروتك والإنترنت (POS System)

تطبيق أندرويد متكامل ومصمم بأسلوب حديث خصيصاً لأصحاب البقالات والمحلات التجارية ليكونوا **نقاط بيع معتمدة (POS)** لشبكات الإنترنت اللاسلكية وشبكات المايكروتك المحلية.

التطبيق مبني وفق معمارية **MVVM + Clean Architecture** بأحدث تقنيات أندرويد المعاصرة:
* **لغة البرمجة:** Kotlin بنسبة 100% مع Coroutines & StateFlow.
* **واجهة المستخدم:** Jetpack Compose بالكامل بالاعتماد على نظام **Material Design 3 (M3)**.
* **قاعدة البيانات المحلية:** **Room Database** بمبدأ (Offline-First) لضمان استمرارية العمل بدون إنترنت والمزامنة الفورية عند الاتصال.
* **الربط الشبكي والمصادقة:** Retrofit 2 + OkHttp 3 + Moshi مع نظام ترويسات أمني واعتراض آلي لتوكن الجلسة (Auth Interceptor).
* **الطباعة الحرارية:** محرك طباعة ESC/POS مباشر يدعم طابعات البلوتوث والشبكة (LAN) ونمط المحاكاة.
* **التوافق والمتطلبات:** متوافق 100% مع متطلبات **Google Play Console (2025/2026)**، مع استهداف `targetSdk = 36` وتفعيل الحافة إلى الحافة (Edge-to-Edge).

## 🏛️ 1. معمارية الربط الشبكي وإدارة الجلسات (Network Architecture & Auth Engine)

### 🔗 عنوان السيرفر الأساسي (Base URL Configuration)
* **المسار الافتراضي للـ API:**
  ```text
  https://cardbox.basmasoft.com/api/
  ```
* **التحكم بالبيئات:** يدعم التطبيق قراءة الرابط من إعدادات البناء `BuildConfig.BASE_URL` تلقائياً عبر ملف `.env`، مع إضافة فاصلة النهاية `/` بشكل آلي في حال نسيانها.

### 🛡️ بروتوكول المصادقة وإدارة الـ Token
1. **تخزين التوكن الآمن (Session Storage):**
   * عند نجاح تسجيل الدخول أو التحقق من رمز OTP، يتم استلام `token` (أو `access_token`) ويُحفظ فورياً في ذاكرة التخزين الدائم `SharedPreferences` تحت الاسم `cardbox_pos_prefs` بمفتاح `auth_token`.
2. **الحقن التلقائي في ترويسة الطلبات (AuthInterceptor):**
   * يقوم الـ Interceptor في `RetrofitClient` بالتحقق من وجود التوكن وإضافته تلقائياً في ترويسة جميع الطلبات:
     ```http
     Authorization: Bearer <AUTH_TOKEN>
     Accept: application/json
     ```
   * لا يحتاج أي استدعاء في كود التطبيق لتمرير التوكن يدوياً، مما يمنع الأخطاء البشرية وتسرب المفاتيح.
3. **مواقيت المهلة ومراقبة الطلبات (Timeouts & Logging):**
   * مهلة الاتصال (Connect Timeout): **15 ثانية**.
   * مهلة القراءة والكتابة (Read/Write Timeout): **20 ثانية**.
   * تفعيل `HttpLoggingInterceptor` بمستوى `Level.BODY` لتتبع كافة تفاصيل الطلبات والردود أثناء التطوير.
4. **عزل الجلسات ومنع تداخل البيانات (User Session Isolation):**
   * عند تسجيل الخروج أو تسجيل الدخول بحساب جديد، يتم استدعاء دالة `clearUserSessionData()` لتفريغ كافة الجداول المحلية السابقة (الحسابات، شبكاتي، المبيعات، المحفظة، الإشعارات) وتطهير التوكن المخزن، لضمان عدم اختلاط سجلات أو أرصدة المتاجر المختلفة على نفس الجهاز.
5. **المزامنة الشاملة عند الدخول (Automatic Full Sync):**
   * بمجرد إتمام الدخول أو استعادة الجلسة، يقوم التطبيق بمزامنة خلفية تشمل:
     - تحديث الملف الشخصي وبيانات المتجر (`syncUserProfile`).
     - جلب رصيد المحفظة وحركاتها اللحظية (`syncWalletBalance`).
     - جلب قائمة الشبكات المعتمدة والسقوف المالية (`fetchMyNetworks`).
     - جلب وتحديث سجل المبيعات والأوردرات (`syncSalesHistory`).

## 📡 2. الفحص الشامل لكافة العمليات والطلبات والردود (Endpoints, Requests & Responses)

فيما يلي التوثيق البرمجي الدقيق لكافة الـ Endpoints في السيرفر مع نماذج الـ JSON للحالات الناجحة وحالات الخطأ:

### 🔑 أ) تسجيل الدخول (POS Login)
* **المسار (Endpoint):** `POST /api/pos/auth/login`
* **الترويسات (Headers):** `Accept: application/json`, `Content-Type: application/json`
* **بيانات الطلب (Request Body):**
  ```json
  {
    "phone": "777123456",
    "password": "mySecurePassword123"
  }
  ```
* **الرد الناجح (Response 200 OK):**
  ```json
  {
    "status": true,
    "message": "تم تسجيل الدخول بنجاح",
    "token": "123|eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "access_token": "123|eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
  ```
* **رد الخطأ (Response 401 Unauthorized / 422 Unprocessable):**
  ```json
  {
    "status": false,
    "message": "بيانات الدخول غير صحيحة. يرجى التأكد من رقم الجوال وكلمة المرور."
  }
  ```
* **سلوك التطبيق محلياً:**
  - تطهير بيانات الجلسة السابقة وحفظ التوكن الجديد.
  - حفظ حساب نقطة البيع في جدول `pos_accounts` بحالة `isLoggedIn = true`.
  - تشغيل المزامنة الشاملة لكافة البيانات تلقائياً.

### 📝 ب) إنشاء حساب نقطة بيع جديدة (POS Registration)
* **المسار (Endpoint):** `POST /api/pos/auth/register`
* **بيانات الطلب (Request Body):**
  ```json
  {
    "name": "أحمد محمد العريقي",
    "shop_name": "بقالة البركة والخير",
    "phone": "777123456",
    "password": "password123",
    "address": "صنعاء - شارع حدة"
  }
  ```
* **الرد الناجح (Response 200 OK):**
  ```json
  {
    "status": true,
    "message": "تم تسجيل الحساب بنجاح، يرجى إدخال رمز التحقق OTP المرسل لهاتفك",
    "test_otp_code": "482910"
  }
  ```
* **رد الخطأ (Response 422 / 400):**
  - يقوم محرك التطبيق (`parseCleanErrorMessage`) بفحص نصوص الخطأ وتصفية أي رسائل تقنية أو SQLSTATE وتحويلها لرسائل واضحة ومفهومة للمستخدم (مثل: "رقم الجوال مسجل مسبقاً لدينا" أو "يرجى التأكد من صحة رقم الجوال").
* **سلوك التطبيق محلياً:**
  - الانتقال التلقائي إلى شاشة التحقق من الـ OTP المكونة من 6 خانات مع تشغيل العداد التنازلي لإعادة الإرسال.

    | محفظة بايس | `Pyes` |

    {
      "success": true,

    - فور التأكيد، يُحدث التطبيق رصيد المحفظة في جدول `wallet_account`، ويُدرج الحركة في `wallet_transactions`، ويطلق إشعار نظام علوي (Heads-Up Notification) في شريط حالة أندرويد.

### 🌐 ط) الشبكات، البحث، وطلب الانضمام (Networks & Join Workflow)
* **1. جلب كافة الشبكات العامة المتاحة:**
  * **المسار:** `GET /api/pos/networks`
  * يعرض قائمة بجميع الشبكات في المدينة/المحافظة مع عدد الباقات وحالة الخدمة.
* **2. جلب شبكاتي المعتمدة لنقطة البيع (My Networks):**
  * **المسار:** `GET /api/pos/networks/my-networks`
  * **الرد الناجح (نموذج شبكة معتمدة):**
    ```json
    [
      {
        "id": 14,
        "network_id": 14,
        "name": "شبكة الأمل اللاسلكية",
        "network_code": "AML-01",
        "governorate": "صنعاء",
        "city": "حدة",
        "status": "approved",
        "credit_limit": 25000.0,
        "current_debt": 6500.0,
        "available_balance": 18500.0
      }
    ]
    ```
  * **استخراج السقف والرصيد والمديونية:**
    يقوم التطبيق بقراءة مرنة لمفاتيح السقف المالي (`credit_limit`, `financial_ceiling`, `limit`) ومفاتيح الرصيد المتاح (`available_balance`, `current_balance`) والمديونية المستحقة لصاحب الشبكة (`current_debt`, `owner_due`) مع حفظها في جدول `joined_networks`.
* **3. إرسال طلب انضمام لشبكة جديدة:**
  * **المسار:** `POST /api/pos/networks/join`
  * **بيانات الطلب:**
    ```json
    {
      "network_id": 14
    }
    ```
  * **الرد:** يوضح حالة الطلب (`pending` قيد الانتظار أو `approved` معتمد ومباشر).
* **4. جلب باقات وكروت شبكة معينة:**
  * **المسار:** `GET /api/pos/networks/{network_id}/packages`
  * **الرد:** مصفوفة بكافة الفئات (`name`, `price`, `pos_price`, `validity`, `description`, `stock`).
  * **المحلل الذكي للمواصفات (`extractPackageSpecs`):**
    يقوم التطبيق بتحليل نص الوصف (`description`) واستخراج:
    1. **السعة والحجم:** استخراج الميجابايت أو الجيجابايت بدقة متناهية (مثل `1 جيجابايت` أو `500 ميجابايت`).
    2. **المدة:** تصحيح الصياغة اللغوية للمدة (مثل: `ساعة واحدة`، `ساعتان`، `5 ساعات`).
    3. **الصلاحية:** تحويل الأرقام إلى أيام وأشهر (مثل: `يوم واحد`، `يومان`، `7 أيام`).

  5. **إدراج الشبكة فورياً في الصفحة الرئيسية («شبكاتي»):** تظهر الشبكة فوراً في قسم «شبكاتي» بالصفحة الرئيسية مع **الحفاظ التام على حالتها الحقيقية الفعلية** (تظهر بشارة «دفع عبر المحفظة» وتبقى غير منضمة إلى أن يتم اعتمادها رسمياً من مالك الشبكة، ولا يتم تحويلها إلى معتمدة تلقائياً)، مع حمايتها واستمراريتها في الواجهة وسجل المبيعات حتى عند مزامنة السيرفر لاحقاً (`fetchMyNetworks`).

### 📊 ك) سجل المبيعات والعمليات (Sales & Order History)
* **المسار:** `GET /api/pos/sales/history`
* **فلترة الاستعلام الاختيارية:** `?filter=today` أو `?filter=all`
* **المطابقة الذكية وإلغاء الازدواجية (Deduplication Engine):**
  - يقوم التطبيق بمطابقة الأوردرات المجلوبة من السيرفر مع الأوردرات المحلية.
  - إذا اشترى العميل كمية متعددة (Grouped Order) وتم تجميع أكواد الـ PIN معاً في سجل محلي، يمنع التطبيق تقسيمها أو تكرارها بناءً على رد السيرفر الفردي.
  - يحافظ التطبيق على حالة طباعة الكرت `isPrinted` واسم نقطة البيع واسم الزبون ورقم هاتفه.

## 🧭 3. الفروقات الجوهرية بين الشبكات المنضم لها والشبكات غير المنضم لها

| وجه المقارنة | الشبكة المنضم لها (Joined / Approved) | الشبكة غير المنضم لها (Unjoined / Public) |
| :--- | :--- | :--- |
| **مكان التواجد والظهور** | تظهر مباشرة في قسم **"شبكاتي"** بالصفحة الرئيسية لسهولة البيع اليومي السريع. | تظهر في شاشة **"الشبكات"** العامة أو من خلال شاشة **"البحث"**. |
| **السقف المالي المتاح (الآجل)** | يمنح مالك الشبكة نقطة البيع **سقفاً ائتمانياً (Credit Ceiling)** تسحب منه كروت حتى حد معين دون دفع مسبق. | لا يوجد سقف مالي على الإطلاق (السقف = 0 ريال)، ولا يوجد حساب آجل مع مالك الشبكة. |
| **طريقة الدفع المعتمدة** | **1. السقف المالي (آجل)** كخيار أول.<br>**2. محفظة كارد بوكس** عند استنفاد السقف المالي. | **الدفع الفوري الحصري** عبر رصيد محفظة كارد بوكس المشحونة نقداً. |
| **لوحة الإحصائيات والمديونية** | لوحة تفاعلية تظهر: الرصيد المتبقي من السقف، إجمالي الكروت المباعة، الأرباح، و**المستحق لمالك الشبكة**. | تعرض متجر الكروت والفئات فقط، ولا توجد مديونية مستحقة أو سقف مالي. |
| **التثبيت وتخصيص الترتيب** | يمكن تثبيتها في أعلى الرئيسية بإطار ذهبي وتقديمها وتأخيرها بأسهم الترتيب. | غير قابلة للتثبيت في الرئيسية إلا بعد الشراء منها أو اعتماد الانضمام. |
| **حالة الشبكة بالواجهة** | شارة خضراء مكتوب عليها **"معتمدة"** وبطاقة جاهزة للبيع بنقرة واحدة. | شارة صفراء **"غير منضم"** أو **"قيد الانتظار"** وزر لطلب الانضمام. |

## 🛒 4. الدليل الكامل لآليات الشراء من كافة الشبكات

### 🟢 أولاً: الشراء من الشبكة المنضم لها (Joined Network)
1. يضغط المستخدم على الشبكة من شاشته الرئيسية فيظهر متجر الكروت بكافة الفئات.
2. يحدد المستخدم الفئة والكمية المطلوبة (عبر أزرار `+` و `-`).
3. يضغط **"شراء الآن"**:
   - يتحقق التطبيق من وجود رصيد كافٍ في **السقف المالي المتاح**.
   - إذا كان الرصيد كافياً: يُرسل الطلب بـ `payment_method = network_credit`، ويُخصم السعر بسعر الجملة (`pos_price`) من السقف المالي، وتزداد مديونية صاحب الشبكة، ويصدر الكود فورياً.
   - **في حال نفاد السقف المالي:** لا تتوقف عملية البيع! تظهر نافذة تنبيه فورية تخبر المستخدم بأن السقف المالي نفد وتمنحه زر: **«إكمال الشراء فوراً عبر رصيد المحفظة»**، فيتم إتمام البيع فوريّاً بالخصم من رصيد محفظة CardBox.

### 🟡 ثانياً: الشراء من الشبكة غير المنضم لها (Unjoined Network)
1. يبحث المستخدم عن أي شبكة عبر الاسم أو الكود أو يستعرض قائمة الشبكات.
2. يدخل مباشرة إلى متجر الكروت ويتصفح الفئات والمواصفات حتى وإن لم يكن معتمداً أو منضماً لها.
3. يحدد الفئة والكمية المطلوبة ويضغط **"شراء عبر المحفظة"**:
   - يتحقق التطبيق من **رصيد محفظة CardBox**.
   - إذا كان رصيد المحفظة يغطي الإجمالي: يُرسل الطلب بـ `payment_method = wallet`، ويُخصم المبلغ فوريّاً من رصيد المحفظة، ويصدر الكود فوراً.
   - **إذا كان رصيد المحفظة غير كافٍ:** تظهر نافذة تنبيه ذكية توضح الرصيد المتبقي والمبلغ المطلوب، مع زر انتقال سريع لشحن المحفظة (عبر الكريمي، جيب، جوالي، ون كاش) والعودة لإتمام الشراء.
4. بمجرد إتمام الشراء، تنضاف الشبكة تلقائياً لقائمة الشبكات في الصفحة الرئيسية لسهولة البيع منها لاحقاً.

## 💾 5. هيكل قاعدة البيانات المحلية (Local Room Database Schema)

يعتمد التطبيق على قاعدة بيانات `AppDatabase` المحلية والتي تتضمن الجداول الأساسية التالية:

1. **`pos_accounts` (حسابات نقاط البيع):**
   - الحقول: `phone` (المفتاح الأساسي)، `storeName`، `location`، `passwordHash`، `isLoggedIn`.
2. **`joined_networks` (الشبكات المعتمدة والمحفوظة):**

3. **`order_transactions` (سجل مبيعات الكروت):**

4. **`wallet_account` (حساب المحفظة المالي):**
   - الحقول: `id`، `balance` (الرصيد النقدي للمتجر).
5. **`wallet_transactions` (حركات المحفظة من إيداعات ومشتريات):**

   - الحقول: `id`، `printerName`، `macAddress`، `isConnected`، `isSimulationMode`.
7. **`app_notifications` (الإشعارات وسجل التنبيهات):**
   - الحقول: `id`، `title`، `message`، `type`، `timestamp`، `isRead`، `relatedEntityId`، `amount`.

## 🖨️ 6. محرك الطباعة الحرارية المباشر (Thermal ESC/POS Engine)

* **خيارات الاتصال:**
  - **طابعات البلوتوث اللاسلكية (Bluetooth SPP):** اقتران مباشر عبر عناوين MAC Address وإرسال أوامر ESC/POS الثنائية.
  - **طابعات الشبكة (LAN / WiFi TCP):** اتصال مباشر عبر بروتوكول Raw Socket على المنفذ القياسي `9100`.
  - **نمط المحاكاة (Simulation Mode):** يتيح معاينة شكل الفاتورة على الشاشة والتأكد من مظهرها دون الحاجة لوجود طابعة فعلية.
* **محتويات الإيصال الحراري:**
  - اسم المتجر ونقطة البيع.
  - اسم الشبكة وعنوانها.
  - **رمز كود الكرت (PIN / Voucher Code)** بخط عريض وواضح وتنسيق مقسم لسهولة القراءة.
  - **باركود أو QR Code** مدمج لتسجيل الدخول السريع في صفحة المايكروتك.
  - مواصفات الباقة (السعر، السعة، المدة، الصلاحية).
  - رقم مرجع العملية وتاريخ ووقت الشراء بالتفصيل.
  - نص تذييل مخصص للمتجر ورقم الدعم الفني.

### 🔐 1. نظام التحقق وتغيير كلمة المرور بالحماية الثنائية (OTP & Account Security)
* **الربط الفعلي مع السيرفر لطلب رمز التحقق (SMS OTP Request):**
  - تم ربط عمليات تغيير وإعادة تعيين كلمة المرور وحذف الحساب مع السيرفر مباشرة عبر الـ Endpoints المخصصة (`/api/pos/password/forgot` و `/api/pos/password/reset`).
  - إظهار مؤشرات تحميل تفاعلية أثناء طلب الرمز لمنع النقر المزدوج والتكرار.
* **نافذة تحقق أمنية تفاعلية متطورة (Interactive 6-Digit PIN Modal):**
  - تصميم واجهة تحقق مخصصة بـ **6 مربعات رقمية مستقلة** مع تأثيرات بصرية عند التركيز، والتحكم التلقائي في مؤشر الكتابة.
  - دعم كامل للوحة المفاتيح الرقمية مع ضبط المسافات التلقائي لمنع حجب الحقول (`imePadding`).
* **عداد تنازلي ذكي لإعادة الإرسال (Countdown Timer Engine):**
  - إضافة عداد زمني (دقيقتين) لمنع الإرسال العشوائي، مع زر تفاعلي **"إعادة إرسال SMS"** ينشط تلقائياً فور انتهاء العداد.
* **إعادة التعيين المباشرة عند نسيان كلمة المرور:**
  - إمكانية إعادة تعيين كلمة المرور فورياً عبر رسالة SMS دون الحاجة لمعرفة كلمة المرور السابقة.
* **تحديث بيانات نقطة البيع:**
  - إمكانية تعديل وحفظ اسم المحل/المتجر والعنوان الجغرافي محلياً وفي السيرفر عبر زر الحفظ المباشر.
* **الحذف الآمن للحساب (Secure Account Deletion):**
  - نافذة تحذيرية مع اشتراط تأكيد رمز OTP لضمان عدم حذف الحساب بالخطأ.

### 🔍 2. محرك البحث والشراء من كافة الشبكات (Universal Network Store & Hybrid Engine)
* **البحث المباشر:** إمكانية البحث السريع عن أي شبكة بالاسم، كود الشبكة، أو المنطقة الجغرافية.
* **الشبكة المنضمة (Joined Network):**
  - تظهر بشارة **"معتمدة"** مع إمكانية استعراض متجر الكروت.
  - إمكانية تثبيت الشبكة (Pin) لتظهر في واجهة التطبيق الرئيسية للوصول السريع.
  - الشراء يخصم من السقف المالي المتاح، وفي حال نفاد السقف المالي يتم الخصم مباشرة وتلقائياً من رصيد المحفظة.
* **الشبكة غير المنضمة (Unjoined Network):**
  - تتيح الدخول المباشر لمتجر الكروت واستعراض الباقات والأسعار دون اشتراط الانضمام المسبق.
  - **الشراء المباشر للجميع:** طالما يمتلك المستخدم رصيداً في محفظته الإلكترونية، يستطيع تحديد الكميات وإتمام الشراء الفوري مع خصم القيمة مباشرة من رصيد المحفظة.

### 💳 3. متجر الكروت وتحليل المواصفات الذكي (Smart Specs Parser)
* **محرك الشراء المزدوج والذكي (Hybrid Purchase Flow):**
  1. **المسار الأول (الشبكات المعتمدة بالسقف المالي):** يخصم مبلغ العملية أولاً من السقف المالي المتاح الممنوح من مالك الشبكة.
  2. **المسار الثاني (المحفظة العامة / نفاد السقف / شبكات غير منضمة):** يتم تحويل الدفع فورياً ليخصم من رصيد المحفظة الرئيسي.
  3. **تغذية سريعة بنقرة واحدة:** إذا كان رصيد المحفظة والسقف غير كافيين، تظهر نافذة تنبيه فورية تتيح الانتقال السريع لشحن المحفظة برقم الإيداع والعودة لإتمام الشراء فوراً.
* **تحليل واستخراج بيانات الكرت الذكي (Smart Specs Parser):**
  - تم إصلاح مشكلة تداخل ونصوص الكروت بحيث يقوم التطبيق باستخراج مواصفات الكرت بدقة متناهية:
    1. **الحجم والسعة (`dataQuota`):** استخراج السعة بدقة (مثل: `350 ميجا` أو `1 جيجا`) وعرضها في خانة الحجم المخصصة.
    2. **المدة الزمنية (`duration`):** استخراج مدة عمل الكرت وصياغتها لغوياً بشكل سليم (مثل: `5 ساعات` أو `ساعتان` أو `24 ساعة`).
    3. **الصلاحية (`validity`):** استخراج مدة الصلاحية وتنسيقها بإضافة التمييز العربي المناسب (مثل: تحويل `5` إلى `5 أيام`).
* **تصميم بطاقة الكرت (Grid Card Design):**
  - جدول مواصفات متناسق بمربعات واضحة وفواصل ناعمة تمنع أي التفاف أو تداخل في النصوص.
  - إبراز اسم الفئة والسعر بعملة الريال مع عداد كميات تفاعلي `+` و `-` نشط ومتاح لكافة الشبكات.
  - شارة توفر الكروت (`متوفر`) وشارة `الأكثر طلباً`.

### 📊 4. محرك الإحصائيات والحسابات اللحظية (Real-Time Stats & Debt Calculation)
* **تحديث فوري لحظي (Zero-Delay Stats):**
  - تم إصلاح آلية احتساب الإحصائيات لتتحدث فورياً وبشكل مباشر بمجرد إتمام الشراء دون الحاجة لمغادرة الشاشة والعودة إليها.
* **القيم المحسوبة بدقة:**
  - **الرصيد المتاح:** يخصم منه سعر الكرت فورياً من السقف المالي `(currentBalance - totalCost)`.
  - **الكروت المباعة:** زيادة فورية في عداد الكروت المباعة وإجمالي المبيعات التراكمية.
  - **المستحق لمالك الشبكة (الآجل):** احتساب مباشر لفارق السقف المالي عن الرصيد المتبقي لإظهار المبلغ الدقيق الواجب تسليمه لصاحب الشبكة.

### 💰 5. تغذية رصيد المحفظة عبر المحافظ الإلكترونية (E-Wallet Top-Up Engine)
* **معايرة أسماء البنوك والمحافظ القياسية (`Bank Name Normalization`):**
  - تم حل مشكلة خطأ عدم العثور على الإيداع عبر مطابقة اسم البنك البرمجي القياسي المطلوب في الـ Backend:
    | المحفظة في الواجهة | المعرف البرمجي المرسل للسيرفر |
    | :--- | :--- |
    | محفظة جيب | `Jaib` |
    | بنك الكريمي (حاسب / ام كريمي) | `Kuraimi` |
    | محفظة جوالي | `Jawali` |
    | محفظة ون كاش | `One_cash` |
    | محفظة فلوسك | `Floosak` |
    | محفظة سبأ كاش | `Saba_cash` |
    | محفظة بايس | `Pyes` |
    | محفظة إيزي | `Easy` |
    | كاش | `Cash_wallet` |
    | جوال | `Jawwal` |

* **نظام المطابقة المالية الثلاثية الصارمة (`Triple Reconciliation Check`):**
  - **التحقق من صحة المبلغ:** يقوم التطبيق بمطابقة المبلغ المدخل من قبل المستخدم مع المبلغ الفعلي المعتمد في السيرفر والحوالة البنكية (`Math.abs(rechargeAmount - expectedAmount) < 1.0`).
  - في حال اختلاف المبلغ المدخل عن مبلغ الحوالة الفعلي، يرفض التطبيق العملية فوراً ويظهر تنبيهاً دقيقاً:
    > *«المبلغ المدخل (X ريال) غير مطابق لمبلغ الحوالة الفعلي بالسيرفر (Y ريال). يرجى تصحيح المبلغ والمحاولة مجدداً.»*
  - **التحقق من اسم المحفظة:** التأكد من تطابق المحفظة المختارة مع المحفظة المودع بها السند بالسيرفر.

* **توصية هامة لمعالجة الحالات الحدية في السيرفر (Backend Anti-Double Spending & Edge Case):**
  - تم توثيق الآلية المثلى للسيرفر: *عند إرسال طلب تغذية برقم مرجعي صحيح ومبلغ غير مطابق، يجب على السيرفر التحقق أولاً من تطابق المبلغ وإبقاء حالة السند معلّقة `pending` (عدم تحويلها إلى `used`) وإرجاع خطأ عدم تطابق المبلغ، حتى لا يفقد العميل حقه في إعادة إدخال المبلغ الصحيح.*

* **نظام إشعارات شريط حالة النظام (System Status Bar & Heads-Up Notifications):**
  - تم إنشاء قنوات إشعارات ذات أولوية قصوى (`IMPORTANCE_HIGH`) مع دعم التنبيه الضوئي والاهتزاز والشارات (`Badges`).
  - دعم كامل لصلاحية إشعارات أندرويد الحديثة (`POST_NOTIFICATIONS` على Android 13+ / Tiramisu).
  - إرسال إشعار بنكي فوري يظهر في شريط الحالة وستارة الإشعارات وشاشة القفل فور نجاح عملية التغذية أو الشراء.
  - إيقاف رسائل الـ Toast المكررة واستبدالها بشرائط تنبيه أنيقة مدمجة داخل التطبيق وفق معايير Material 3.

### 🛡️ 8. أمان وخصوصية التعبئة التلقائية لرموز التحقق (OTP Autofill Security & Threat Modeling)
* **كيف تعمل التعبئة التلقائية لأكواد التحقق في أندرويد؟**
  - يتم جلب الرمز من خلال واجهة النظام الرسمية المشفرة **Google SMS Retriever API / Android Autofill Framework**.

* **هل يستطيع مخترق أو تطبيق آخر معرفة رمز التحقق؟**
  - **منع التدخل الخارجي (App Sandboxing):** تطبيقات أندرويد معزولة في بيئة حماية صارمة (Sandbox). لا يمكن لأي تطبيق آخر التلصص على ما يكتب في واجهة تطبيقك.
  - **ميزة One-Time Password:** رمز الـ OTP صالح للاستخدام لمرة واحدة فقط ولدقائق معدودة (2 دقيقة) ثم ينتهي تماماً ولا يمكن إعادة استخدامه.

### 💰 9. نظام مزامنة سجل عمليات المحفظة والمطابقة الشاملة (Universal Wallet History Sync & Reconciliation)
* **دعم كافة أشكال JSON لسجل العمليات من السيرفر:**
  - تم تحويل استجابة الـ API لجلب بيانات وسجل المحفظة (`/api/pos/wallet/balance`) إلى قراءة ديناميكية مرنة تدعم كافة التنسيقات والمفاتيح (`transactions`, `recent_transactions`, `history`, `recharges`, `data`).
  - استخراج ذكي للحقول المختلفة من السيرفر مثل (`recharge_id`, `transaction_id`, `ref_id`, `created_at`, `timestamp`).
* **تخزين محلي فوري ومزامنة سحابية (Offline-First Local Storage + Cloud Sync):**
  - يتم حفظ عمليات الإيداع والتغذية المكتملة في قاعدة بيانات `Room` المحلية فور إتمام العملية بنجاح.
  - المزامنة التلقائية مع السيرفر عند سحب الشاشة للتحديث أو الدخول لشاشة المحفظة دون حذف أو إخفاء العمليات السابقة.
* **إصلاح قيود الفلترة وإلغاء التكرار (Smart Deduplication):**
  - تم ربط معرفات الطلبات وعمليات شراء الكروت بالرقم المرجعي المشترك (`referenceNumber` و `order.id` و `tx-cb-{order.id}`).
  - تم حل مشكلة ظهور شراء الكرت مرتين في سجل المحفظة من خلال منع إدراج العملية المكررة عند دمج جدول الحركات المالية `walletDao` مع جدول المبيعات `orderDao`.
* **إرشادات لمطور السيرفر حول استهلاك السندات (Backend Recommendation):**
  - يُوصى بعدم استهلاك السند أو الرقم المرجعي أو تحويل حالته إلى `used` إلا بعد اكتمال التحقق وتطابق المبلغ المدخل مع المبلغ المسجل بالسند، حتى لا يتم حرق السند في حال أخطأ العميل بكتابة المبلغ في المحاولة الأولى.
  - **حماية القنوات المشفرة (TLS 1.3 Encryption):** الاتصال بين التطبيق وسيرفر الـ API مشفر بالكامل ولا يمكن اعتراضه عبر الشبكة (MitM Protection).

    3. **حذف من الرئيسية (Remove from Home):** زر أحمر بارز لحذف الشبكات المحددة من الصفحة الرئيسية مع نافذة تأكيد مطمئنة تؤكد بقاء كافة الكروت والمبيعات السابقة وإمكانية العودة للشبكة في أي وقت عبر البحث.
